# StudyHour

Рабочее full-stack приложение для предзаказа учебных ИИ-инструментов. Чёрно-синий интерфейс, отдельная мобильная навигация, вход по email и паролю, личный кабинет и админка.

**Стек:** React + TypeScript + Vite; Node.js 24; SQLite. Cloudflare, D1 и платная облачная БД не нужны. SQLite — база в файле; хостинг приложения и постоянный диск нужны отдельно.

## Работает сейчас

- Регистрация, вход, выход; пароли scrypt + соль; HttpOnly / SameSite cookie, Secure при HTTPS; ограничение попыток входа.
- Профиль, изменение имени и пароля. Смена пароля завершает остальные сессии.
- Каталог, поиск, фильтры, выбор пакета и удобного времени.
- Бронирование максимум на 7 дней вперёд: колёсики даты, часов и минут (только 00/30), время Казахстана UTC+5. Прошедшие слоты скрыты; те же ограничения проверяются сервером.
- Серверный расчёт цены, бронирования в SQLite, история и отмена своих заявок.
- Администратор видит заявки и скачивает настоящую таблицу `.xlsx`. В Excel нет паролей и сессий.
- Изоляция данных между учениками, проверка Origin для изменений, параметризованные SQL-запросы.
- Мобильная версия: нижняя навигация, крупные кнопки, форма бронирования снизу экрана.

## Быстрый запуск

Установите Node.js **24+** (используется встроенный `node:sqlite`).

```bash
npm ci
npm run dev
```

Откройте адрес, напечатанный сервером (обычно http://localhost:5173). SQLite создаётся автоматически в `.data/studyhour.sqlite`. Данные сохраняются между перезапусками. Каталог `.data` и `.env` исключены из Git.

## Production

```bash
npm ci
npm run check
npm test
npm run build
cp .env.example .env
# Укажите в .env свой APP_ORIGIN, например https://studyhour.example
npm start
```

Для сайта в интернете нужен HTTPS reverse proxy и **постоянный диск**. При HTTPS cookie автоматически получает Secure. На временном диске serverless-хостинга SQLite не сохранится после перезапуска контейнера. Не используйте несколько независимых реплик с разными файлами базы. Сама SQLite не требует оплаты; стоимость сервера зависит от размещения.

Вариант с Docker:

```bash
APP_ORIGIN=http://localhost:3000 docker compose up --build -d
```

Для своего домена задайте APP_ORIGIN=https://your-domain.example и настройте HTTPS reverse proxy. Volume `studyhour-data` хранит базу независимо от контейнера. Не запускайте `docker compose down -v`, если хотите сохранить данные.

## Админка

1. Зарегистрируйте свой аккаунт через сайт.
2. Выполните **на сервере**:

```bash
npm run admin -- your@email.example
# Docker:
docker compose exec studyhour node server/admin.mjs your@email.example
```

3. Откройте личный кабинет: появятся заявки и кнопка «Скачать Excel».

Роль нельзя получить через клиентский запрос или выбор email; её назначает владелец сервера командой. Первый зарегистрированный пользователь автоматически админом не становится.

## Хранение и резервные копии

База: `.data/studyhour.sqlite`, рядом могут быть файлы WAL/SHM. Не копируйте только основной файл работающей базы без согласованного backup: используйте `VACUUM INTO` через SQLite или остановите приложение и скопируйте весь каталог `.data`. Excel — выгрузка заявок, не резервная копия аккаунтов.

## Что требует подключения перед продажами

- Платёжный провайдер, merchant-реквизиты, webhook проверки оплаты и возвраты.
- Реальное разрешённое предоставление ИИ-доступа и лимиты сессий.
- Разрешённая интеграция Turnitin. Загрузка документов и поддельные отчёты не реализованы.
- Email-провайдер для подтверждения почты и самостоятельного восстановления пароля. Сейчас email используется как логин без подтверждения; пароль можно поменять из кабинета, зная текущий.

До этого сервис явно работает как **предзаказ**: не списывает деньги и не заявляет, что ИИ-доступ выдан. Личные пароли ChatGPT/Claude/Gemini не собираются. Названия Plus/Pro — позиции каталога, не доказательство интеграции.

## Проверки

```bash
npm test
npm run check
npm run build
```

Интеграционные тесты поднимают отдельный локальный HTTP-сервер и временную SQLite, проверяют регистрацию, вход, хеширование, профиль, изменение пароля, сессии, ограничения попыток, расчёт цен, отмену, запрет доступа к чужим заявкам, права администратора, Excel и сохранение данных после переоткрытия базы. 11 комбинаций тарифов + 4 недопустимых выбора покрыты тестами. Excel также проверен через openpyxl.

## Структура

- `src/Dashboard.tsx` — каталог и бронирования.
- `src/Account.tsx` — вход, регистрация, кабинет, админка.
- `src/catalog.ts` — каталог и тарифы.
- `server/app.mjs` — API.
- `server/database.mjs` — схема SQLite.
- `server/security.mjs` — scrypt, сессии, rate limit.
- `server/excel.mjs` — XLSX без внешних сервисов.
- `tests/app.test.mjs` — проверки.
